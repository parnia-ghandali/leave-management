# سامانه مدیریت مرخصی کارکنان — Front-end

داشبورد مدیریتی فارسی و راست‌چین برای بررسی، تأیید و رد درخواست‌های مرخصی که ربات تلگرام (n8n) جمع‌آوری می‌کند.
این نسخه **فقط Front-end** است (HTML + CSS + JavaScript خالص، بدون نیاز به build) و با داده آزمایشی کار می‌کند.

## ساختار پوشه‌ها

```
leave-dashboard/
├── index.html              # تنها صفحه (ورود + داشبورد + مودال‌ها)
├── .nojekyll               # جلوگیری از پردازش Jekyll در GitHub Pages
├── README.md
└── assets/
    ├── favicon.svg
    ├── css/
    │   └── style.css       # استایل‌ها و واکنش‌گرایی
    └── js/
        ├── config.js       # تنظیمات (USE_MOCK، آدرس API)
        ├── utils.js        # تاریخ شمسی، ارقام فارسی، escape
        ├── mock-data.js    # داده آزمایشی + ذخیره در LocalStorage
        ├── api.js          # لایه API (Mock و HTTP واقعی)
        ├── auth.js         # ورود نمایشی
        └── app.js          # منطق رابط کاربری
```

## اجرا روی سیستم خودتان

پروژه نیازی به نصب پکیج ندارد. یکی از روش‌های زیر:

- **ساده‌ترین:** فایل `index.html` را مستقیم در مرورگر باز کنید.
- **با وب‌سرور محلی (پیشنهادی):** داخل پوشه پروژه یکی از دستورها را اجرا کنید و آدرس `http://localhost:8000` را باز کنید:
  ```bash
  python3 -m http.server 8000
  # یا
  npx serve .
  ```

**ورود نمایشی:** نام کاربری `admin` — رمز عبور `admin123`

> فونت Vazirmatn از CDN (jsDelivr) بارگذاری می‌شود. بدون اینترنت، فونت جایگزین (Tahoma) استفاده می‌شود و بقیه برنامه عادی کار می‌کند.

## انتشار روی GitHub Pages (مرحله‌به‌مرحله)

1. در GitHub یک مخزن (Repository) جدید بسازید، مثلاً `leave-dashboard`.
2. محتوای پوشه پروژه را در ریشه مخزن قرار دهید (`index.html` باید در ریشه باشد).
   ```bash
   cd leave-dashboard
   git init
   git add .
   git commit -m "Initial commit: leave dashboard front-end"
   git branch -M main
   git remote add origin https://github.com/<USERNAME>/leave-dashboard.git
   git push -u origin main
   ```
3. در GitHub به **Settings → Pages** بروید.
4. در بخش **Build and deployment**، گزینه Source را روی **Deploy from a branch** بگذارید.
5. Branch را `main` و پوشه را `/ (root)` انتخاب و **Save** کنید.
6. چند دقیقه صبر کنید. آدرس سایت به این شکل نمایش داده می‌شود:
   `https://<USERNAME>.github.io/leave-dashboard/`

تمام مسیرها نسبی هستند، بنابراین نیازی به تنظیم اضافه برای زیرمسیر مخزن نیست.

## داده‌های آزمایشی

- ۱۲ درخواست نمونه با وضعیت‌ها و نوع‌های مختلف ساخته می‌شود.
- تاریخ‌ها نسبت به «هفته جاری (شنبه تا جمعه)» تولید می‌شوند تا بخش «مرخصی‌های این هفته» همیشه نمونه داشته باشد.
- تغییر وضعیت‌ها در `LocalStorage` مرورگر ذخیره می‌شود. برای بازنشانی، در کنسول مرورگر اجرا کنید:
  ```js
  localStorage.removeItem('leave_demo_requests_v1'); location.reload();
  ```
- تاریخ‌ها داخل داده‌ها میلادی (ISO) هستند و فقط هنگام نمایش به شمسی تبدیل می‌شوند. ورودی تاریخ در فیلترها شمسی است (مثلاً `1405/08/10`).

## اتصال به Backend در آینده

1. در `assets/js/config.js` مقدار `USE_MOCK` را `false` و `API_BASE_URL` را آدرس سرویس خود (مثلاً روی Render) بگذارید.
2. Backend باید این endpointها را ارائه دهد (پیاده‌سازی `fetch` آن در `assets/js/api.js` آماده است):

| عملیات | متد و مسیر |
|---|---|
| لیست درخواست‌ها | `GET /requests` |
| جزئیات درخواست | `GET /requests/:id` |
| تأیید | `PATCH /requests/:id/approve` |
| رد | `PATCH /requests/:id/reject` |
| گزارش هفتگی | `GET /reports/weekly?from=YYYY-MM-DD&to=YYYY-MM-DD` |

3. شکل هر درخواست (JSON):
   ```json
   {
     "id": "LR-1405-0001", "fullName": "...", "nationalId": "...", "telegramId": "...",
     "leaveType": "daily | hourly | sick", "startDate": "2026-11-02", "endDate": "2026-11-04",
     "startTime": "10:00", "endTime": "13:00", "createdAt": "2026-10-27",
     "reason": "...", "status": "pending | approved | rejected"
   }
   ```
4. ورود: `Auth.login` در `assets/js/auth.js` باید با `POST /auth/login` جایگزین شود و توکن (ترجیحاً کوکی HttpOnly) از سرور بگیرد.

## محدودیت‌های نسخه فعلی

- **ورود فقط نمایشی است** و هیچ امنیتی ندارد؛ نام کاربری و رمز در کد قابل مشاهده‌اند.
- داده‌ها فقط در مرورگر همان کاربر ذخیره می‌شوند؛ بین دستگاه‌ها یا کاربران همگام نمی‌شوند.
- تأیید یا رد از طریق ربات تلگرام به کارمند اطلاع داده **نمی‌شود** (این کار با n8n/Backend انجام می‌شود).
- جستجو و فیلتر روی کل لیست در مرورگر انجام می‌شود؛ برای حجم بالا باید صفحه‌بندی و فیلتر سمت سرور اضافه شود.
- ثبت لاگ حسابرسی (چه کسی، کی تأیید کرد)، نقش‌های کاربری و محافظت در برابر تأیید همزمان فقط با Backend ممکن است.

## نیازمندی‌های Backend

- احراز هویت و مجوزدهی واقعی (JWT یا Session) با HTTPS.
- دیتابیس درخواست‌ها و endpointهای جدول بالا، همراه با اعتبارسنجی ورودی‌ها.
- نگهداری **توکن ربات تلگرام و کلیدهای API فقط در سمت سرور** (متغیرهای محیطی).
- تنظیم CORS فقط برای دامنه GitHub Pages خودتان.
- مخفی‌سازی یا ماسک کردن بخشی از کد ملی در پاسخ‌ها در صورت نیاز (داده شخصی حساس).
- (اختیاری) Webhook برای اطلاع‌رسانی نتیجه به کارمند از طریق ربات.
